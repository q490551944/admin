# 共享后台采集调度

监控在应用就绪后后台解析已存在的连接，并运行共享采集任务。页面读取当前快照，不触发采集。`monitor.enabled=false` 时不解析连接，也不启动监控工作线程。

普通采集默认每 15 秒一次、8 个工作槽；容量采集默认每 60 秒一次、2 个独立工作槽。两个执行池各有最多 `max-targets` 个排队位置。已解析目标按稳定 ID 顺序错峰；错过的轮次直接跳过，不通过补发旧任务追赶。

## 总预算与故障隔离

默认 5 秒预算从进入调度队列开始计算。执行使用单调时钟，保留最多 100 毫秒的结论发布时间；传给适配器的剩余时间包含排队消耗。截止协调线程不运行适配器，也不关闭网络资源。

- 没有开始执行的绑定在截止时记录 `BUSY`，并从工作队列移除。
- 正在执行的绑定在截止时记录 `FAILED` 与 `TIMEOUT`。
- 适配器在预算内返回的原生失败、授权不足和不支持等原因直接保留。
- 缺少已注册适配器时记录 `UNSUPPORTED`，不导致应用启动失败。
- 调度故障保留已有指标的最后成功值与原有效期；没有历史指标时使用采集结果自身的原因字段。调度器不会据此制造远端服务宕机结论。

一个目标同一类别最多有一个真实存活任务，排队期间也占用这一资格。普通和容量任务可以同时运行。已超时但尚未退出的请求保留占位，后续轮次只能得到繁忙结论；不会继续创建替代线程或在调用线程执行任务。

## 资源归属与取消契约

适配器通过 `CollectionRequest.control()` 获取本次请求的剩余预算、取消状态及计数计算入口。所有原生操作都必须使用剩余时间设置连接、读取或请求超时；可取消的请求同时登记原生取消/关闭动作。`Future.cancel(true)` 只用于协作中断，不能替代协议级终止。

资源登记受上限约束。先预留登记位置，再创建监控自己拥有的请求或连接，并把取消动作绑定到预留位置；取消与资源创建发生竞争时，晚到的资源仍会被清理。完成的登记需注销，尚未创建资源的预留需释放。不能登记关闭借用的业务客户端、连接工厂或池。

清理在独立的固定大小执行池中运行，队列有界，拒绝后由协调器重试登记的清理动作。清理不会在截止协调线程或生命周期锁内同步执行。仅当工作线程已经返回且全部登记清理结束时，才释放目标占位。坏适配器忽略中断时仍被限制在固定的线程、任务与登记上限内；支持某种真实中间件的采集器必须另外证明自己的原生超时和取消可以实际结束请求。

清理动作抛出异常时也保留占位，不重复执行可能不幂等的动作；后续轮次显示繁忙。适配器需保证正常完成后资源已经终止，再注销登记。

## 来源绑定与采样计算

Redis 的多个配置目标可能合并成一个显示目标。每个绑定仍保留自己的客户端、来源与允许范围，并在同一个目标任务内共享截止时间。不会把显示层的范围并集传给任意一个来源。

`bindingId` 使用原配置目标 ID，`source` 保留实际连接来源名。快照、序号、完整清单退役、服务探测以及计数基线按绑定和采集类别隔离。同一个 bean 的两个不同范围可以在同一序号分别提交，不会相互删除指标。

计数计算在请求中暂存候选样本。只有当前代次、预算内的绑定结果被快照接纳后，候选基线才一起提交。超时、取消、旧代次及容量拒绝都不能更改下一轮计算使用的基线。只有明确完整的清单可以退休该绑定下已经消失的计数系列。

## 生命周期

默认只在应用就绪后解析一次连接，不实现配置热加载。受控替换整批目标时分配新代次，取消旧请求并清除相应当前状态；即使配置目标 ID 相同，旧结果也不能提交到新代次。更换实际客户端需要受控替换或应用重启；服务本身重启仍由适配器的原生运行标识及计数回退规则识别。

关闭监控先停止新任务并关闭结果接纳，再取消已经登记的监控请求。共享业务客户端不由监控关闭。清理执行器保留到登记资源实际清理完成；未终止的坏请求不会使关闭操作无限等待。
