# Issue #7：员工搜索与唯一私聊

实现 `GET /api/chat/v1/users?query=...` 和 `POST /api/chat/v1/direct-conversations`，并接入现有聊天页面。文字发送、ACK 和历史查询继续使用已有消息链路。

## 接口

员工搜索按现有 `user.username` 做不区分大小写的包含查询，排除当前用户及 `status` 非真的账号。查询去除首尾空格，最多 100 个字符；空查询返回前 30 个同事，非空查询也最多返回 30 个。`%`、`_`、`!` 按字面搜索。当前员工表没有姓名和头像字段，所以 `name` 返回用户名，`avatar` 为 null，由前端生成文字头像。

```json
[{"userId":"2","name":"bob","avatar":null}]
```

发起私聊请求使用 `{"peer_user_id":"2"}`，兼容 `peerUserId`。发起人只取 Session，客户端不能指定。新建或重复打开均返回 200 和会话投影，其中 `id`、`peerUserId` 为字符串，`name` 为相对于请求用户的对方用户名。缺失、自身、非正数、小数、布尔值或超出 Long 范围的目标返回 422；不存在或停用的目标返回 404。写接口要求 Session 与 CSRF。

## 并发与权限

- `direct_key` 按数值排序为 `较小用户ID:较大用户ID`，复用数据库 `(type, direct_key)` 唯一约束。
- 在同一事务中按 ID 顺序锁定双方账号，复核状态，再读取或创建私聊及两条参与记录。任一参与记录写入失败时全部回滚。共享同一账号的私聊创建会短暂串行执行。
- 重复打开是只读操作，不额外锁定会话，避免与消息写入的会话锁、用户外键检查形成反向锁序。重复请求不更新活跃时间，也不恢复失效的参与关系。
- 会话列表、消息历史、STOMP 发送和订阅只对私聊双方开放。第三方访问已有活动私聊返回 403，并写入 `AUTH_DENIED`。
- 越权审计在原事务完成后通过新事务保存，既不随拒绝请求回滚，也不在原事务仍持锁时进行外键检查。
- `/api/chat/v1/attachments/{id}/content` 与 `/thumbnail` 在读取处理器之前，根据附件真实的 `conversation_id` 执行同一权限检查。查询参数中的会话 ID 不参与授权。

Issue #7 最初只建立附件路径的会话权限边界。后续已接入真实附件处理器、存储读取及 IMAGE 发送，当前图片协议与验证记录见 [剩余卡片交付记录](chat-completion.md)。

## 页面

打开私聊弹窗立即搜索真实员工。旧搜索结果不会覆盖新查询，登录失效后的响应不会恢复页面数据。创建期间阻止重复提交，重复打开不增加会话列表条目，并重新同步历史。用户 ID 全程保留字符串，私聊成员区显示当前用户和对方，不再回退到演示人物或推断在线状态。
