SEQUENCE DIAGRAM

企业聊天室发送消息时序

STOMP SEND → 会话鉴权 → 幂等落库 → 事务提交 → 实时广播 → 私有 ACK

序列图 — 依据聊天室 SPEC 描述目标交互契约；当前仓库只完成持久化基础，图中 Handler、拦截器与 after-commit 广播仍属于待实现能力。

SECURITY

认证与会话权限

  • • 使用 Session Cookie，不使用消息 Token
  • • CONNECT / SUBSCRIBE / SEND 均由拦截器校验
  • • 私聊仅双方可见，解散会话禁止继续发送
  • • 失败通过 `/user/queue/chat.errors` 返回

IDEMPOTENCY

幂等与事务

  • • `clientRequestId` 为必填字段
  • • 唯一键：`(sender_id, client_request_id)`
  • • 重复发送返回已有消息，不重复落库
  • • 消息先提交数据库，再进入广播阶段

DELIVERY

广播与确认

  • • after-commit 发布 `MESSAGE_CREATED`
  • • 会话成员订阅隔离的 conversation Topic
  • • 发送方通过私有 ACK 队列获得确认
  • • 图片消息只广播受保护的附件引用

RECOVERY

失败与补偿

  • • 广播失败不回滚已持久化消息
  • • 写入审计事件并触发可观测告警
  • • 客户端可通过历史消息 REST 接口补拉
  • • 错误语义与 REST 的 401/403/409 等保持一致
